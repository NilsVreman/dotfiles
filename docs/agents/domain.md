# Domain Docs

## Before exploring

This repo uses a single-context layout:

- Read root `GLOSSARY.md` for domain vocabulary.
- Read relevant decisions in `docs/adr/`.

If these files are absent, proceed silently.
The domain-modeling skill creates them lazily when terms or decisions are resolved.

## Use the glossary's vocabulary

Use defined terms in issue titles, proposals, hypotheses, and tests.
For a missing concept, reconsider the wording or note the gap for domain-modeling.

## Flag ADR conflicts

Explicitly identify any existing ADR your proposal contradicts, and explain why reopening the decision may be worthwhile.
